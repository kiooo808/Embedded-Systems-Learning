## 第一节：代码优化

### 1.1 内存优化
```c
// ESP32-S3 内存分配策略
// 片上 SRAM: 512KB (高速)
// PSRAM: 8MB/16MB (大容量，但较慢)

// 动态内存分配
#include "esp_heap_caps.h"

// 分配到 PSRAM（大容量）
void *buf = heap_caps_malloc(1024, MALLOC_CAP_SPIRAM);

// 分配到内部 RAM（高速）
void *fast_buf = heap_caps_malloc(256, MALLOC_CAP_INTERNAL);

// 分配到 DMA 可用内存
void *dma_buf = heap_caps_malloc(4096, DMA_CAP_DMA);

// 分配到 DRAM（支持 DMA）
void *dram_buf = heap_caps_malloc(4096, MALLOC_CAP_DMA);

// 检查内存状态
esp_heap_caps_get_free_size(MALLOC_CAP_INTERNAL);
esp_heap_caps_get_free_size(MALLOC_CAP_SPIRAM);
esp_heap_caps_get_minimum_free_size(MALLOC_CAP_ANY);

// 释放内存
free(buf);

// 使用 PSRAM 需要在 menuconfig 中启用
// Component config → ESP PSRAM → Enable PSRAM
```

### 1.2 代码优化技巧
```c
// 1. 减小任务堆栈
// 默认堆栈可能过大，实际测量后调整
// 使用 uxTaskGetStackHighWaterMark() 检查
void check_stack_usage(TaskHandle_t task)
{
    UBaseType_t high_water = uxTaskGetStackHighWaterMark(task);
    ESP_LOGI("STACK", "Min free stack: %d words", high_water);
    // 如果 high_water > 500，可以减小堆栈
}

// 2. 使用静态分配（避免动态分配开销）
// FreeRTOS 任务静态创建
static StackType_t xTaskBuffer[configMINIMAL_STACK_SIZE];
static StaticTask_t xTaskStruct;

TaskHandle_t task = xTaskCreateStatic(
    task_func, "task",
    configMINIMAL_STACK_SIZE,
    NULL, 1,
    xTaskBuffer, &xTaskStruct
);

// 3. 使用 IRAM_ATTR 优化中断
// 中断处理函数放到 IRAM（避免 Cache 未命中）
void IRAM_ATTR isr_handler(void *arg)
{
    // 中断代码
}

// 4. 使用 ICACHE_RODATA_ATTR 优化只读数据
// 常查表放到 Flash Cache
const char ICACHE_RODATA_ATTR menu[] = 
    "This is a long string that stays in cache";

// 5. 减少 printf 开销
// 使用 ESP_LOG 级别控制
esp_log_level_set("*", ESP_LOG_ERROR);  // 只显示错误
esp_log_level_set("my_module", ESP_LOG_INFO);  // 特定模块

// 6. 使用 DMA 减少 CPU 占用
// SPI、UART、I2C 等外设使用 DMA 传输
```

### 1.3 CPU 优化
```c
// 双核分配
// Core 0: Wi-Fi、BT、协议栈
// Core 1: 用户任务

// 将高优先级任务绑定到特定核心
xTaskCreatePinnedToCore(task_func, "task", 
    stack_size, param, priority, &handle, 1);  // Core 1

// 避免在 Core 0 执行耗时操作
// Wi-Fi 和 BT 需要 Core 0 的 CPU 时间

// 使用中断优先级
// 0 (最高) ~ configMAX_SYSCALL_INTERRUPT_PRIORITY (最低)
// 建议：
//   - 系统关键中断: 5
//   - 外设中断: 4
//   - 用户中断: 2-3
//   - 不使用: 0-1

// 关闭不用的外设时钟
periph_module_disable_clock(PERIPH_MODULE_xxx);

// 使用轻量级 API
// 避免在中断中执行 printf、malloc 等操作
```

## 第二节：低功耗设计

### 2.1 ESP32-S3 低功耗模式
```
ESP32-S3 低功耗模式：
├── Active Mode
│   - CPU 运行，所有外设可用
│   - 功耗: ~80mA @ 240MHz
│
├── Modem Sleep
│   - CPU 运行，Wi-Fi/BT 关闭
│   - 功耗: ~20mA
│   - 恢复: 快速
│
├── Light Sleep
│   - CPU 暂停，部分外设保持
│   - 功耗: ~0.8mA
│   - 恢复: ~2ms
│
├── Deep Sleep
│   - 大部分模块关闭
│   - 功耗: ~10uA
│   - 恢复: 重新启动（~100ms）
│   - 可以唤醒源: GPIO、RTC、定时器
│
└── Hibernation
    - 最深度睡眠
    - 功耗: ~1uA
    - 仅 ULP 协处理器可用
```

### 2.2 Light Sleep 实现
```c
#include "esp_sleep.h"
#include "driver/gpio.h"

void enter_light_sleep(void)
{
    // 配置唤醒源
    // GPIO 唤醒
    esp_sleep_enable_ext0_wakeup(GPIO_NUM_0, 0);  // 低电平唤醒
    
    // 定时器唤醒
    esp_sleep_enable_timer_wakeup(10000000);  // 10 秒后唤醒
    
    // 进入 Light Sleep
    esp_err_t ret = esp_sleep_light_sleep();
    // 唤醒后继续执行
}

void enter_deep_sleep(void)
{
    // 配置唤醒源
    esp_sleep_enable_timer_wakeup(60000000);  // 60 秒
    
    // 保存状态到 RTC 内存
    // RTC 内存在 Deep Sleep 中保持
    
    // 进入 Deep Sleep
    esp_deep_sleep_start();
    // 唤醒后重新启动（相当于复位）
}

// ULP 协处理器（超低功耗）
// ESP32-S3 有 RISC-V ULP 协处理器
// 可以在 Deep Sleep 中运行
#include "ulp_riscv/ulp_core.h"

void ulp_init(void)
{
    // 配置 ULP
    ulp_riscv_config_t cfg = {
        .timeout = 1000,
    };
    ulp_riscv_init(&cfg);
    
    // 加载 ULP 固件
    ulp_riscv_load_binary(ulp_bin, ulp_bin_size);
    
    // 设置唤醒周期
    ulp_riscv_set_period(1000000);  // 1 秒
    
    // 启动 ULP
    ulp_riscv_run();
}
```

## 第三节：常见问题与解决方案

### 3.1 编译问题
```
Q: 编译时出现 "error: 'xxx' was not declared"？
A: 
1. 检查头文件是否正确包含
2. 检查 CMakeLists.txt 中 REQUIRES 是否包含依赖组件
3. 检查组件是否已正确注册
4. 清理后重新编译：idf.py fullclean && idf.py build

Q: 出现 "undefined reference to 'xxx'"？
A:
1. 检查 CMakeLists.txt 中 SRCS 是否包含源文件
2. 检查函数名是否正确拼写
3. 检查是否有条件编译导致函数未编译

Q: 编译错误 "section .text' will not fit in region 'iram0.text'"？
A:
1. IRAM 溢出，增大 CONFIG_ESP_SYSTEM_MEMPROT_MAX_IRAM_SIZE
2. 或将代码移到 Flash（不使用 IRAM_ATTR）
3. 关闭不用的功能（如 PSRAM、SPIFFS 等）
```

### 3.2 烧录问题
```
Q: 烧录失败 "Failed to connect to ESP32-S3"？
A:
1. 检查 USB 连接和数据线
2. 尝试按住 BOOT 按键再复位
3. 降低波特率：idf.py -p COM3 -b 115200 flash
4. 检查驱动：设备管理器中是否有未知设备

Q: 烧录后一直重启？
A:
1. Strapping 引脚配置错误
   - GPIO0: 应为高电平（Flash 启动）
   - GPIO45/46: 检查启动模式
2. 固件损坏，尝试烧录官方示例
3. Flash 损坏

Q: 烧录后什么都不输出？
A:
1. 检查串口监视器是否连接正确
2. 检查波特率是否为 115200
3. 检查 TX/RX 是否接反
4. 尝试 GPIO43(TX) 调试口
```

### 3.3 运行问题
```
Q: 程序启动后立即重启？
A:
1. 检查堆栈大小是否足够
2. 检查是否有野指针操作
3. 查看 Core Dump 信息
   - idf.py monitor 查看错误日志
   - 或使用 GDB 调试

Q: 出现 "Guru Meditation Error"？
A:
1. 这是 ESP32 的 Panic Handler
2. 查看错误类型：
   - LoadProhibited: 访问无效内存
   - StoreProhibited: 写入无效内存
   - InstrFetchProhibited: 从无效地址取指
   - StackOverflow: 栈溢出
   - IllegalInstruction: 非法指令
3. 使用 Core Dump 分析
   -启用 CONFIG_ESP_COREDUMP_ENABLE_TO_FLASH
   - 烧录后运行，读取 Core Dump
   - 使用 espcoredump.py 分析

Q: Wi-Fi 连接不稳定？
A:
1. 检查信号强度：esp_wifi_sta_get_ap_info()
2. 尝试不同的信道
3. 检查天线连接
4. 使用 esp_wifi_set_bandwidth() 设置带宽

Q: BLE 连接失败？
A:
1. 检查是否在广播：esp_ble_gap_set_device_name()
2. 检查 GATT 服务是否注册
3. 检查手机兼容性
4. 尝试低功耗模式

Q: UART 接收数据丢失？
A:
1. 增大 UART 缓冲区
2. 使用 DMA 接收
3. 降低波特率
4. 使用流控（如果对方支持）
```

### 3.4 Core Dump 分析
```c

void hexdump(const uint8_t *data, int len)
{
    for (int i = 0; i < len; i += 16)
    {
        printf("%04x: ", i);
        for (int j = 0; j < 16 && (i + j) < len; j++)
        {
            printf("%02x ", data[i + j]);
        }
        printf("\n");
    }
}
```
